# Migration 手順書

この手順書は `DotNetStarterProject` で Entity Framework Core migration を作成・適用するための手順です。
Migration は DB 変更の履歴なので、初回作成、認証追加、テーブル追加のように変更単位で順番に作成します。

## 前提

- PostgreSQL が起動していること
- `appsettings.json` の `DefaultConnection` が正しいこと
- `Microsoft.EntityFrameworkCore.Design` が参照されていること
- `Npgsql.EntityFrameworkCore.PostgreSQL` が参照されていること
- `ApplicationDbContext` に対象の Entity / Identity 設定が反映されていること

現在の接続先:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=8888;Database=sandbox;Username=postgres;Password=postgres"
  }
}
```

## 基本コマンド

Migration 作成:

```bash
dotnet ef migrations add <MigrationName> --project DotNetStarterProject/DotNetStarterProject.csproj
```

DB 反映:

```bash
dotnet ef database update --project DotNetStarterProject/DotNetStarterProject.csproj
```

Migration 一覧確認:

```bash
dotnet ef migrations list --project DotNetStarterProject/DotNetStarterProject.csproj
```

## 推奨する作成順

### 1. 初回 migration

アプリケーションの最初の DB 定義を作成した時点で実行します。

```bash
dotnet ef migrations add Init --project DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef database update --project DotNetStarterProject/DotNetStarterProject.csproj
```

`Init` は最初の基準点です。
後から認証や追加テーブルを入れる場合でも、最初の DB 構造をここで固定しておくと履歴が追いやすくなります。

### 2. User / Identity 追加

`ApplicationUser`、`ApplicationDbContext : IdentityDbContext<ApplicationUser>`、`Program.cs` の Identity 登録を追加した後に実行します。

```bash
dotnet ef migrations add AddIdentity --project DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef database update --project DotNetStarterProject/DotNetStarterProject.csproj
```

作成される主な Identity テーブル:

```text
AspNetRoleClaims
AspNetRoles
AspNetUserClaims
AspNetUserLogins
AspNetUserRoles
AspNetUserTokens
AspNetUsers
```

このリポジトリでは以下の Identity migration が作成済みです。

```text
DotNetStarterProject/Migrations/20260523000103_AddIdentity.cs
DotNetStarterProject/Migrations/20260523000103_AddIdentity.Designer.cs
DotNetStarterProject/Migrations/ApplicationDbContextModelSnapshot.cs
```

### 3. Place テーブル追加

`Place` モデルと `ApplicationDbContext` の `DbSet<Place>` を追加した後に実行します。

```bash
dotnet ef migrations add AddPlaces --project DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef database update --project DotNetStarterProject/DotNetStarterProject.csproj
```

以降も、テーブルやカラムを変更したタイミングで migration を追加します。

例:

```bash
dotnet ef migrations add AddPlaceAddress --project DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef database update --project DotNetStarterProject/DotNetStarterProject.csproj
```

## テーブル確認

psql で確認する場合:

```bash
docker exec postgres-sandbox psql -U postgres -d sandbox -c "select tablename from pg_tables where schemaname = 'public' order by tablename;"
```

Identity テーブルだけ確認する場合:

```bash
docker exec postgres-sandbox psql -U postgres -d sandbox -c "select tablename from pg_tables where schemaname = 'public' and tablename like 'AspNet%' order by tablename;"
```

## Migration を作る前の確認

Migration 作成前に、対象の変更が `ApplicationDbContext` から見える状態になっている必要があります。

確認するもの:

- Entity クラスを作成しているか
- `ApplicationDbContext` に `DbSet<T>` を追加しているか
- Identity の場合は `IdentityDbContext<ApplicationUser>` を継承しているか
- `Program.cs` で `AddDbContext` と `AddIdentity` を登録しているか

## よくあるエラー

### `No migrations were found`

Migration がまだ作成されていない、または migration ファイルがプロジェクトに含まれていない可能性があります。

通常は手書きせず、以下で生成してください。

```bash
dotnet ef migrations add <MigrationName> --project DotNetStarterProject/DotNetStarterProject.csproj
```

### `PendingModelChangesWarning`

現在の `ApplicationDbContext` と `ApplicationDbContextModelSnapshot` が一致していません。
既存 migration を手で直すのではなく、新しい migration を追加します。

```bash
dotnet ef migrations add <ChangeName> --project DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef database update --project DotNetStarterProject/DotNetStarterProject.csproj
```

作成直後の migration をやり直す場合だけ、以下で戻してから作り直します。

```bash
dotnet ef migrations remove --project DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef migrations add <MigrationName> --project DotNetStarterProject/DotNetStarterProject.csproj
```

### EF tools のバージョン警告

例:

```text
The Entity Framework tools version '10.0.5' is older than that of the runtime '10.0.8'.
```

警告だけで migration の作成・適用が成功している場合は動作上の問題はありません。
気になる場合は `dotnet-ef` を runtime に合わせて更新します。

```bash
dotnet tool update --global dotnet-ef
```

## 実行後の確認

```bash
dotnet build DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef database update --project DotNetStarterProject/DotNetStarterProject.csproj
dotnet ef migrations list --project DotNetStarterProject/DotNetStarterProject.csproj
```

`Build succeeded.` と `Done.` が表示されれば適用完了です。
